# PersonalClaw 架构

## 一、架构定位

PersonalClaw（PC）定位是 **AI Agent 操作系统内核**。

```
┌─────────────────────────────────────────────────────────────┐
│                      Agent 应用层                            │
│  (唯一的 Agent：通过 config.yml 配置)                         │
└─────────────────────────────────────────────────────────────┘
                             │
┌─────────────────────────────────────────────────────────────┐
│                      插件层                                  │
│  ┌──────────┐                                    │
│  │  Channel  │  (Telegram、飞书、Discord)              │
│  └──────────┘                                    │
└─────────────────────────────────────────────────────────────┘
                             │
┌─────────────────────────────────────────────────────────────┐
│                      PC 核心                                │
│  (Agent 生命周期、插件系统、通信协议、权限控制、记忆系统)       │
│  - LLM 调用：BAML 内置 (baml_src/)                              │
│  - Tool 执行：builtin (internal/engine/builtin/)               │
└─────────────────────────────────────────────────────────────┘
```

## 二、核心约束

| 约束 | 说明 |
|-----|------|
| 核心零依赖 | 核心不包含任何第三方 SDK（LLM/Channel SDK） |
| 插件独立演化 | Channel 插件是独立进程，独立维护 |

## 三、配置结构

### 3.1 主配置

```yaml
# ~/.pc/config.yml
agent:
  name: PersonalClaw
  profession: 通用助手

system_prompt:
  file: ~/.pc/agents.md

workspace: ~/workspace
```

### 3.2 插件配置

```bash
~/.pc/plugins/
└── channel/
    └── telegram/
        ├── plugin.yml          # 插件元信息
        ├── config.yml          # 插件配置
        └── bin/telegram-bot    # 可执行文件
```

## 四、Gateway 架构

- **传输层**: Unix Socket (`~/.pc/pc.sock`)
- **协议**: JSON-RPC 简化版
- **TUI**: 通过 RPC 与 Gateway 通信，不维护状态

## 五、技术选型

| 层级 | 选型 | 说明 |
|-----|------|------|
| 语言 | Go 1.25+ | 高并发、跨平台 |
| LLM | BAML | 内置到主进程 |
| 日志 | logo | 控制台+文件输出 |
| 协议 | stdio (JSON) | 插件通信 |
| 配置 | YAML | 人类可读 |

## 六、编码规范

### 6.1 语言和格式

- Go 1.25+，使用 `go fmt` 格式化
- 不添加代码注释（除非明确要求）
- 优先 `var` 声明而非 `:=`

```go
// 推荐
var name string = "example"
var count int = 10

// 避免
name := "example"
```

### 6.2 Imports

两组分隔：标准库 + 第三方

```go
import (
    "context"
    "fmt"
    
    "github.com/lixianmin/logo"
)
```

### 6.3 命名

| 类别 | 规范 | 示例 |
|------|------|------|
| Receiver | `my` | `func (my *Engine) Process()` |
| 缩写 | CamelCase | `sessionId` 不是 `sessionID` |
| 文件 | 反映类型 | `skill_manager.go` → `SkillManager` |
| ID | ULID | `github.com/oklog/ulid/v2` |

### 6.4 类型

- 用 `any` 代替 `interface{}`
- 一个实现时不定义接口

### 6.5 错误

- 显式处理（不可协商）
- 用 `%w` 包装

```go
if err != nil {
    return fmt.Errorf("failed: %w", err)
}
```

### 6.6 函数

- 单一职责
- 预分配 slice
- 尽早返回

### 6.7 Goroutine

**强制**: 用 `loom.Go()`

```go
import "github.com/lixianmin/got/loom"

loom.Go(func(later loom.Later) {
    my.backgroundTask()
})
```

### 6.8 日志

- 库: `github.com/lixianmin/logo`
- 禁止 `fmt.Println()`（CLI 交互除外）

```go
logo.Info("[Session:", sessionId, "] User:", message)
```

### 6.9 配置

- 格式: YAML
- 主配置: `~/.pc/config.yml`
- 解析: `gopkg.in/yaml.v3`

## 七、测试

### 7.1 Table-Driven

```go
func TestProcess(t *testing.T) {
    tests := []struct {
        name    string
        input   string
        wantErr bool
    }{
        {"valid", "hello", false},
        {"empty", "", true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // test
        })
    }
}
```
