# PersonalClaw 架构

## 一、架构定位

PersonalClaw（PC）是定位是 **AI Agent 操作系统内核**。

```
┌─────────────────────────────────────────────────────────────┐
│                      Agent 应用层                            │
│  (唯一的 Agent：通过 config.yml 配置)                         │
└─────────────────────────────────────────────────────────────┘
                             │
┌─────────────────────────────────────────────────────────────┐
│                      插件层                                  │
│  ┌──────────┐                                    │
│  │  Channel  │  (Telegram、飞书、Discord)              │
│  └──────────┘                                    │
└─────────────────────────────────────────────────────────────┘
                             │
┌─────────────────────────────────────────────────────────────┐
│                      PC 核心                                │
│  (Agent 生命周期、插件系统、通信协议、权限控制、记忆系统)       │
│  - LLM 调用：BAML 内置 (baml_src/)                              │
│  - Tool 执行：builtin (internal/engine/builtin/)               │
└─────────────────────────────────────────────────────────────┘
```

## 二、核心原则

| 原则 | 说明 |
|-----|------|
| 核心零依赖 | 核心不包含任何第三方 SDK（LLM/Channel SDK） |
| 插件独立演化 | Channel 插件是独立进程，独立维护 |
| 最大化利用三方工具 | 不重复实现已有能力 |

## 三、目录结构

```
 pc/
├── cmd/pc/              # 主程序入口
│   ├── main.go
│   ├── root.go
│   ├── tui.go
│   ├── gateway/       # gateway 子命令
│   └── task/          # task 子命令
├── internal/
│   ├── agent/         # Agent 管理
│   ├── engine/        # 核心引擎
│   │   └── builtin/    # 内置工具 (bash, read, write, edit, glob, grep)
│   ├── gateway/       # Gateway daemon
│   ├── llm/           # BAML 客户端封装
│   ├── plugin/        # 插件系统
│   ├── memory/        # 记忆系统
│   ├── tui/           # TUI 界面
│   └── config/        # 配置管理
├── baml_src/            # BAML 定义（LLM 客户端配置）
├── baml_client/        # 自动生成，不要手动编辑
└── examples/
    └── plugins/       # 示例插件（仅 Channel）
```

## 四、配置结构

### 4.1 主配置文件

```yaml
# ~/.pc/config.yml
agent:
  name: PersonalClaw
  profession: 通用助手
  personality:
    - 友好
    - 专业

system_prompt:
  file: ~/.pc/agents.md

workspace: ~/workspace
log_level: info
```

### 4.2 插件目录

```bash
~/.pc/plugins/
└── channel/
    └── telegram/
        ├── plugin.yml          # 插件元信息
        ├── config.yml          # 插件配置参数
        └── bin/telegram-bot    # 插件可执行文件
```

## 五、Gateway 架构

### 5.1 通信协议

- **传输层**: Unix Socket (`~/.pc/pc.sock`)
- **协议**: JSON-RPC 简化版
- **权限**: 文件权限 0600（仅当前用户）

### 5.2 启动流程

```
pc gateway start
    │
    ▼
检查 pidfile → 初始化 Gateway → 加载配置 → 启动 RPC Server
```

### 5.3 TUI 架构

TUI 通过 Unix Socket RPC 与 Gateway 通信，不维护状态。所有状态由 Gateway 统一管理。

## 六、技术选型

| 层级 | 技术选型 | 说明 |
|-----|---------|------|
| 核心语言 | Go 1.25+ | 高并发、跨平台 |
| LLM 调用 | BAML | 内置到主进程 |
| 日志 | github.com/lixianmin/logo | 支持控制台和文件输出 |
| 协议 | stdio (JSON) | 插件通信 |
| 配置 | YAML | 人类可读 |

## 七、编码规范

### 7.1 命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| Receiver | 统一使用 `my` | `func (my *Engine) Process()` |
| 文件命名 | 反映主要类型名 | `skill_manager.go` → `SkillManager` |
| ID 生成 | ULID | `ulid.Make().String()` |

### 7.2 Goroutine 管理

**强制要求**: 使用 `loom.Go()` 启动 goroutine

```go
import "github.com/lixianmin/got/loom"

loom.Go(func(later loom.Later) {
    my.backgroundTask()
})
```

### 7.3 配置规范

- **格式**: YAML (`.yml`)，不使用 JSON
- **插件配置**: `~/.pc/plugins/<type>/<name>/config.yml`
