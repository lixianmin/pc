## 项目概述

PersonalClaw（简称 PC）是一个开源的 AI Agent平台，目标是成为agent时代的linux操作系统微内核。

### 项目定位：AI Agent 操作系统内核

**PC 的定位类似于 Linux 内核**：

| 层级 | Linux | PersonalClaw |
|-----|-------|--------------|
| **内核层** | Linux 内核（进程管理、内存管理、文件系统、设备驱动） | PC 核心（Agent 管理、插件系统、通信协议、权限控制） |
| **内核模块** | 内核模块（网络驱动、文件系统驱动） | 内置插件（基础协议实现） |
| **用户空间** | 系统工具、应用程序、第三方软件 | 外部插件（LLM Provider、Web Search、Channel、Tool） |

**核心理念**：

- PC 核心只提供**基础设施**和**能力框架**
- 所有具体能力（LLM Provider、Web Search、Channel、Linux 命令、三方 API）都由**独立项目**实现
- PC 通过**标准化协议**与这些插件通信，实现能力的最大化利用

### 什么是自托管 AI 代理平台？

自托管 AI 代理平台指的是：
- 用户在自己的服务器或本地设备上运行的独立程序（单一可执行文件 `pc`）
- 平台运行一个唯一的 AI Agent，作为用户的数字助手
- 不依赖第三方云服务，数据和隐私完全由用户控制
- 通过插件系统，最大化利用现有的三方工具（Linux 命令、API、服务等）

### Agent 定义

PersonalClaw 运行时只有一个唯一的 Agent，它是用户的数字助手，具备以下属性：

| 属性 | 描述 |
|-----|------|
| **名字** | Agent 的名字，可在 config.yml 中配置 |
| **性格** | Agent 的行为风格、说话方式、决策偏好（可选配置） |
| **技能列表** | 从 skills 目录自动加载的能力集合 |
| **记忆** | Agent 的长期记忆，包含过往经验、用户偏好等 |

### 插件化架构的设计目标

PersonalClaw 采用插件化架构的核心原因：

| 设计目标 | 说明 |
|---------|------|
| **最大化利用三方工具** | 任何现有的 Linux 命令、三方 API、服务都可以通过插件接入，不需要重新实现 |
| **第三方独立演化** | LLM Provider、Web Search、Channel、Tool 各自独立发展，由各自的社区维护 |
| **零依赖原则** | 核心项目不包含任何第三方 SDK，保持纯粹的基础设施定位 |
| **解耦与隔离** | 每个插件都是独立的进程，可以独立开发、测试、部署、升级 |
| **可替换性** | 插件可以随时替换，不影响核心和其他插件运行 |
| **跨语言支持** | 插件可以用任何语言实现，通过 stdio 等通用协议与核心通信 |

**插件类型与示例**：

| 插件类型 | 作用 | 示例 |
|---------|------|------|
| **LLM Provider 插件** | 对接各种大语言模型服务 | OpenAI、Anthropic、本地 Ollama、Google Gemini |
| **Web Search 插件** | 对接各种搜索引擎或搜索服务 | Google、Bing、SerpAPI、本地向量搜索 |
| **Channel 插件** | 对接各种通讯渠道 | Telegram、飞书、Discord、Slack、WeChat |
| **Tool 插件** | 对接各种外部工具 | Linux 命令（ls、grep）、Git、Docker、Jira API、Notion API |

**核心不做什么**：

- ❌ 不实现 OpenAI API 调用
- ❌ 不实现 Telegram Bot 逻辑
- ❌ 不实现 Google 搜索
- ❌ 不实现文件系统操作（通过 Tool 插件调用系统命令实现）
- ❌ 不实现任何第三方 SDK 依赖

**核心做什么**：

- ✅ 定义插件接口和通信协议
- ✅ 管理 Agent 生命周期
- ✅ 协调插件调用
- ✅ 处理插件之间的数据流转
- ✅ 提供安全隔离和权限控制

### 核心愿景

PersonalClaw 的终极目标是成为用户的数字助手：

> "在我上班的路上，在我睡觉的时候，PC 会默默地自主去完成我需要它做的任务。它能自己去赚钱，自己去开发项目，甚至自己迭代自己的代码。"

**自主性能力**：
- 自主完成任务：根据用户设定的高层目标，自主分解并执行
- 自主决策：根据环境和记忆，做出合理的决策
- 自主学习：从执行过程中学习，优化自己的行为
- 自主进化：能够修改和迭代自己的代码，提升能力

**任务文件格式**：

**task_list.md** - 待办任务列表（运行时动态维护）

```markdown
# 待办任务列表

## [IN_PROGRESS] 部署 v1.0.0
- 创建时间: 2026-02-25 10:00
- 进度: 3/5
  - [x] 代码审查
  - [x] 运行测试
  - [x] 构建镜像
  - [ ] 部署到生产环境
  - [ ] 验证部署

## [PENDING] 修复登录页面 Bug
- 创建时间: 2026-02-25 14:30
- 进度: 0/2
  - [ ] 定位问题
  - [ ] 修复并测试

## [COMPLETED] 更新依赖库
- 创建时间: 2026-02-24 16:00
- 完成时间: 2026-02-24 17:00
```

**heartbeat.md** - 周期性任务配置

```markdown
# 心跳任务配置
# 定义需要定期执行的任务

## 每天凌晨 2 点检查项目健康
schedule: "0 2 * * *"
description: 检查项目编译是否通过、测试是否通过
on_failure: 通知用户

## 每周日上午 10 点生成周报
schedule: "0 10 * * 0"
description: 总结本周工作进展，生成周报发送给用户
on_failure: 忽略
```

| 阶段 | 目标 | 交付物 | 状态 |
|-----|------|--------|------|
| Milestone 1: 核心框架 | Agent 生命周期 + 插件接口定义 | 可运行的 PC，无实际能力 | ✅ 完成 |
| Milestone 2: 最小可用 | 1 LLM 插件 + 1 Channel 插件 | 能对话的 Agent | ✅ 完成 |
| Milestone 3: 基础能力 | Web Search 插件 + Tool 插件 + 基础 Skill | 能执行简单任务 | ✅ 完成 |
| Milestone 4: 多 Agent | 支持多个 Agent + 职业 + 技能系统 | 多角色协作 | ✅ 完成 |
| Milestone 5: 自主性 | 目标管理 + 自主任务分解 | 半自主运行 | 🔄 部分完成 |
| Milestone 6: 自我进化 | 代码访问 + 自我修改能力 | 真正自主进化 | 🔄 代码完成，待集成 |
| **Milestone 7: CLI & Gateway** | **Daemon 模式 + TUI 交互界面** | **可用的命令行工具** | **✅ 完成** |
