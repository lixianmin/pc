# Todo Dispatch

## 执行步骤

### 1. 阅读阶段

按顺序读取以下文件：
1. `notes/00.constitution.md` - 理解核心纪律
2. `notes/05.todo.md` - 获取待整理的临时需求
3. `notes/01.spec.md` - 需求文档（真理之源）
4. `notes/02.arch.md` - 架构设计
5. `notes/03.task.md` - 现有任务清单

### 2. 分析阶段

对 05.todo.md 中的每一项：
- 判断是**需求**还是**架构设计**
- 需求 → 更新到 01.spec.md（添加需求条目）
- 架构 → 更新到 02.arch.md（添加架构章节）
- 确保引用 01.spec.md 中的需求编号

### 3. 更新阶段

#### 更新 01.spec.md
- 在对应章节添加新需求
- 分配需求编号（如 CLI-010）
- 设置优先级（P0/P1/P2/P3）
- 更新变更记录

#### 更新 02.arch.md
- 在对应章节添加架构设计
- 添加实现细节或技术方案
- 更新架构图（如需要）
- 更新变更记录

### 4. 编译阶段

更新 03.task.md：
- 新增任务条目（格式：M{里程碑}-{序号}）
- 填写：优先级、需求编号、架构映射
- 编写详细实现步骤（宪法 1.3 要求）
- 编写验收标准（含测试要求）
- 更新里程碑完成率
- 更新代码 TODO 汇总
- 更新架构映射总览图
- 更新变更记录

### 5. 清理阶段

清空 05.todo.md（内容已整理到其他文件）

## 注意事项

- **不要修改 03.task.md 中已完成的任务状态**
- **必须基于 01.spec.md（真理之源）进行整理**
- **新任务必须包含详细实现步骤和验收标准**
- **必须更新所有文件的变更记录**
